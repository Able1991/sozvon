# Контракт приложения и движка

Приложение Sozvon (Swift) и движок (Python, `engine/`) общаются только через то, что описано здесь:
переменные окружения, файл настроек `.env`, аргументы командной строки, файлы в папке звонка,
коды завершения и строки протокола в выводе. Всё остальное внутреннее и может меняться.

Версия контракта: **1**. Ломающее изменение повышает версию и требует миграции на обеих сторонах.

## 1. Папки

| Что | Где | Кто пишет |
|---|---|---|
| Данные движка (`SOZVON_DATA_DIR`) | `~/Library/Application Support/Sozvon` | приложение копирует код, `setup.sh` ставит окружение |
| Код движка | `<data>/server.py`, `install.py`, `models.py`, `sozvon_engine/`, `bin/`, `models.json`, `pyproject.toml`, `uv.lock`, `.python-version`, `setup.sh`, `vocab.default.json`, `ENGINE_VERSION` | приложение из бандла при смене `ENGINE_VERSION` |
| Окружение Python | `<data>/.venv` | `setup.sh` (`uv sync --frozen`) |
| Модели | `<data>/models/<dir>/` + метка `.complete` | установщик по `models.json` |
| Проекты | `<data>/profiles/<slug>.json` | приложение, движок, MCP |
| Последний ответ поиска проектов | `<data>/profiles/.discover-last.txt` (сырой текст помощника, для разбора ошибок; перезаписывается при каждом поиске) | `bin/discover_projects.py` |
| Общий словарь | `<data>/vocab.json` | движок, MCP |
| Звонки (`SOZVON_CALLS_DIR`) | `~/Documents/Calls/<id>[ · проект · тема · люди]/` | приложение и движок |

Метки состояния движка в `<data>`: `.engine-version` (версия скопированного кода),
`.venv-lock` (хеш `uv.lock`, под который собрано окружение), `.installed` (время установки),
`.no-diarization` (модели разбивки по голосам не установились), `.mcp-token` (пароль MCP, права 600).

## 2. Переменные окружения

Приложение задаёт их при каждом запуске движка. `.env` в папке данных читается движком как
значения по умолчанию; переменные окружения важнее `.env`.

| Переменная | Значение | Кто задаёт |
|---|---|---|
| `SOZVON_DATA_DIR` | папка данных движка | приложение |
| `SOZVON_CALLS_DIR` | папка звонков | приложение |
| `SOZVON_UI_LANG` | `ru` или `en`: язык сообщений движка и файлов расшифровки | приложение |
| `SOZVON_THREADS` | предел потоков на обычных ядрах (режим «Не мешать работе») | приложение |
| `SOZVON_MCP_PORT`, `SOZVON_MCP_TOKEN` | порт и пароль общего MCP-сервера | приложение |
| `SOZVON_PYANNOTE_TAR` | путь к архиву моделей разбивки в бандле | приложение (для `setup.sh`) |
| `SOZVON_PYANNOTE_URL`, `SOZVON_PYANNOTE_SHA` | другой адрес и SHA-256 архива моделей разбивки (для разработки) | никто по умолчанию |

Ключи `.env` (пишет приложение из настроек, `SOZVON_ENV_VERSION=1`):

| Ключ | Значения |
|---|---|
| `SOZVON_ME` | как подписывать пользователя |
| `SOZVON_LLM` | `claude`, `codex`, `none`, `auto` |
| `SOZVON_SUMMARY_MODEL` | модель Claude для саммари, определения имён и поиска проектов (по умолчанию `sonnet`) |
| `SOZVON_LANGUAGE` | языки звонков: `ru`, `ru,en`, `auto` |
| `SOZVON_LANG_SWITCH` | `1`: определять язык каждой фразы |
| `SOZVON_MODEL` | ключ из `models.json`: `turbo`, `large-v3`, `small`, `gigaam`, `parakeet` |
| `SOZVON_SMART_NAMES` | `0`: не определять имена собеседников через помощника |
| `SOZVON_CODEX_MODEL` | модель Codex (`codex exec -m`); пусто: модель по умолчанию из настроек Codex. Приложение не пишет, только для ручной настройки |
| `HF_TOKEN` | необязательный токен Hugging Face |

## 3. Командная строка

`bin/process_call.py <папка звонка>` расшифровывает звонок. Всё о звонке берётся из `call.json`;
аргументы ниже только переопределяют его поля (для ручного запуска и тестов):
`--profile`, `--names`, `--topic`, `--terms`, `--language`, `--speakers`, `--switch`,
`--no-diarize`, `--no-summary`, `--me`.

`bin/discover_projects.py` ищет проекты. `server.py` запускает MCP по stdio, `server.py --http`
общий сервер на `127.0.0.1:$SOZVON_MCP_PORT` с bearer-токеном. `models.py <data> <модель>` скачивает модель.
`install.py <data>` (его вызывает `setup.sh` после `uv sync`) ставит модель из `SOZVON_MODEL`,
модели разбивки по голосам и метки `.venv-lock`, `.installed`, `.no-diarization`; строки прогресса
начинаются с `==> `.

## 4. Папка звонка

```
2026-11-04 15-01 · Acme · запуск · Анна/
  mic.m4a, system.m4a     дорожки (AAC)
  call.json               метаданные (ниже), источник правды
  meta.json               старые звонки: смещения дорожек (приложение больше не пишет, движок читает, если в call.json нет audio)
  transcript.md / .txt    расшифровка
  summary.md              саммари (если было)
  process.log             журнал расшифровки
```

Имя папки только для человека. **id звонка** это минута начала записи `2026-11-04 15-01`;
вторая и следующие записи, начатые в ту же минуту, получают суффикс: `2026-11-04 15-01-2`,
`2026-11-04 15-01-3`. id всегда лежит в `call.json` (`"id"`), приложение пишет его сразу при
создании папки, и он главный. Разбор имени нужен только папкам без `call.json`: id это начало имени
по шаблону `^\d{4}-\d{2}-\d{2} \d{2}-\d{2}(-\d+)?(?= |$)`, для старых папок это первые 16 символов.
Приложение создаёт папку только новой (существующую не принимает) и при сбое запуска удаляет
лишь свою пустую папку. Папка переименовывается после успешной расшифровки, начало имени (id)
при этом не меняется, поэтому id стабилен (по нему ищут MCP-инструменты).

`call.json`, схема 1:

```json
{
  "schema": 1,
  "id": "2026-11-04 15-01",
  "created_at": "2026-11-04T11:01:13Z",
  "status": "recorded | processing | done | failed",
  "audio": {"mic_start": 3764879.93, "system_start": 3764879.64, "mic_seconds": 1755.6, "system_seconds": 1755.8},
  "profile": "acme", "names": ["Анна"], "topic": "запуск", "terms": "",
  "languages": "ru,en", "summary": true,
  "engine": {"version": "aad392548a91a7b4", "model": "turbo"}
}
```

Приложение создаёт файл при остановке записи (`status: recorded`, `audio`) и дописывает ответы
из окна «О чём был звонок» (`profile`, `names`, `topic`, `terms`, `languages`, `summary`).
Движок ставит `processing`, затем `done` и `engine` (версия из `ENGINE_VERSION` рядом с `server.py`,
иначе из `.engine-version`). Поля, заданные аргументами командной строки, движок тоже записывает
в `call.json`: с ними звонок и расшифрован. Битый `call.json` движок не перезаписывает (код 2).
При ошибке приложение ставит `failed`.
Запись атомарная: временный файл и переименование.

Проекты `profiles/<slug>.json` и словарь `vocab.json` тоже несут `"schema": 1`. Имя проекта
только `[a-z0-9_-]{1,64}`.
Движок и MCP правят их («прочитать, изменить, записать») под `flock` на соседнем файле
`<файл>.lock` (`profiles/<slug>.json.lock`, `vocab.json.lock`); кто пишет эти файлы, берёт ту же блокировку.

## 5. Коды завершения и протокол вывода

| Код | Значение | Что показывает приложение |
|---|---|---|
| 0 | готово | открыть расшифровку |
| 2 | нет звука ни на одной дорожке / неверный ввод | «В записи нет звука», проверить разрешения |
| 3 | движок сломан (импорт, окружение) | предложить переустановить движок |
| 4 | модель не скачана | предложить скачать модель |
| 5 | ffmpeg не смог прочитать запись | «Запись повреждена» |
| 1 | прочая ошибка | журнал |

Код 2 также: нет папки звонка, битый `call.json`, неизвестная модель в `SOZVON_MODEL`.
Код 3 также: не найден `ffmpeg` в окружении. Расшифровка пишется до саммари: сбой саммари или
определения имён не меняет код 0.

Последняя строка вывода `bin/process_call.py`: `RESULT: ok` или `RESULT: error <код> <сообщение>`.
`bin/discover_projects.py` пишет промежуточные строки `STATUS: <текст>`.
Сообщения на языке `SOZVON_UI_LANG`.
